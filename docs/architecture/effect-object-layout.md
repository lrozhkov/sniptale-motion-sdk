# Local Effect v1 objects

`objectLayout` is optional and only applies to standalone effects. Its dimensions describe the stable logical object box, not the video frame and not the current nontransparent pixels. Position and rotation belong to the host clip. The graph draws in object coordinates; duplicating scene placement in graph controls creates two competing transforms.

`resize: "scale"` preserves the declared aspect ratio. The interpreter evaluates `width` and `height` at the declared natural size and uniformly fits that object into the requested logical viewport. An oversized viewport receives centred transparent letterboxing; it is a preview surface, not the selection bounds. Hosts use `resolveEffectV1ObjectLayout` to obtain the fitted object dimensions and use those dimensions for the actual clip and selection. Dragging a single dimension must derive the other dimension from the aspect ratio before invoking the resolver. The resolver fits a box; it does not infer which handle the user dragged.

`resize: "reflow"` evaluates the graph at the host's requested logical dimensions. It supports independent width and height changes. Stroke and typography stay constant only when the author expresses them in local units rather than multiplying them by frame size. Raster sampling resolution remains separate from logical geometry. The host must rerender after resize; stretching a cached bitmap would distort the stroke.

The object box is independent of time, text and control values. Internal text or row changes do not change the clip transform. Authors must reserve suitable internal space or publish another layout; this contract does not implement text measurement or automatic wrapping. Without external handles, the interpreter clips painting to the declared object viewport. Arbitrary overflow and external shadows are not implied by the contract. Alpha scanning must never determine selection bounds, especially during fades or path reveals.

Without `objectLayout`, existing documents keep their full-viewport rendering semantics. Target effects and transitions retain their input-frame geometry. Their internal mask windows require separate host editing affordances and must not be treated as standalone object bounds. Hosts must preserve the optional field through snapshotting, cloning, export and reimport. Older validators reject the added field; deploy updated validation and rendering together before importing new object documents. No existing project should be silently reframed from its current pixels.

## External point handles

A scale object can declare up to eight `handles`. Each handle names two separate bounded number controls in local logical units, has a localized label and specifies padding around its endpoint. The graph must observe those controls and draw its geometry inside the union of the body rectangle and the padded points. Numeric coordinate limits are safety bounds, not scene coordinates or an instruction to expose a million-unit slider. The host presents a point handle on the scene and constrains pointer input to that scene.

`resolveEffectV1ObjectRenderBounds(layout, controls)` returns this union as a local rectangle, including negative origins when a point lies above or left of the body. It depends on controls, never on time or alpha. `objectLayout.width/height` continue to describe only the body selection. The sandbox retains natural body width/height in graph scope and uniformly fits the expanded render rectangle into its requested viewport. Therefore a host must request and composite the expanded rectangle, not squeeze its bitmap into the body clip. Direct preview in a fixed viewport deliberately zooms out to show the entire union.

For a body placement with scale `s`, request logical render dimensions `bounds.width * s` and `bounds.height * s`. Before rotation, composite at `body.x + bounds.x * s`, `body.y + bounds.y * s`. For rotation, transform this local render rectangle around the body centre with the same matrix as the body. Selection and hit testing for the card remain attached to the body box; the point has its own hit target. Bitmap density is a separate concern. A distant point may require host culling or reduced raster density; allocating the natural coordinate bounds as device pixels is incorrect.

`mapEffectV1ObjectPoint` initializes the scene position of an authored local default. The host owns and persists the scene anchor in the effect instance. `mapEffectV1ScenePoint` converts that scene anchor back to graph control values for the current body transform; rotation is in radians about the body centre. Recompute these effective values after moving, scaling or rotating the body, preserving the scene anchor. Dragging the point changes the scene anchor without changing the body transform. A group move may intentionally transform both as one explicit operation. Do not persist both a scene anchor and independently mutable local coordinates as competing authorities. Export a portable effect by baking the currently derived local coordinates; save the project with its scene anchors and body transform.

The authoring graph decides how to attach the leader to the body and what to do when the point enters it. The callout templates choose a side from the point direction and hide the leader inside the card. These are template behaviours, not special cases in the renderer. Effects without handles keep their previous clipping and resize semantics.
