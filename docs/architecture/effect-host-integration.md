# Effect host integration

Effect documents own deterministic rendering and declarative parameter metadata. Hosts own clip, track and aggregate targets, placement, timing, enabled state, processing order and editing history. A document does not contain a project scene assignment. Catalog identifiers are stable technical keys; display names come from localized labels under the shared [i18n contract](i18n-architecture.md).

## Parameter presentation

Controls may declare `group`, a safe semantic identifier, and `order`, a non-negative safe integer. Known groups are content, typography, appearance, geometry, processing, animation and advanced. The host owns group labels, icons and group order. Unknown well-formed groups produce a warning and appear in Advanced; malformed presentation is an import error. Missing presentation remains valid; host fallback must not infer meaning from template or parameter identifiers. Equal order values retain document order.

Number and text controls may declare 2–64 localized `options`. Values must be unique, match the control kind and numeric range, and include the default. Options do not create a new control kind. A number option remains a number through UI, snapshot and export. Colors cannot declare options. Editing defaults must retain the presentation fields and result in a valid document. Schema validation handles structure; runtime validation additionally checks cross-field membership, ranges and uniqueness.

Text controls may declare `localizedDefaultValue`, a locale map with a nonblank English `en` fallback, alongside the required literal string `defaultValue`. Locale keys and resolution follow the shared i18n contract: case-insensitive exact locale, base language, then English. Empty optional translations fall back; an intentionally empty field should omit the map and keep an empty literal default. Number and color controls reject this field. For text options every nonblank localized default must be an option value. The public `resolveEffectV1ControlDefault(control, locale)` helper accepts validated controls and resolves a starting value only when the host creates a new instance. Without the map it returns the literal default. The host stores that resolved primitive in instance controls. Locale changes, restore, reload, duplication and history never resolve defaults again or overwrite stored values, including empty strings. Parser, normalization and the SDK authoring viewer retain literal defaults and localized metadata unchanged; opening an effect document for authoring is not instance creation. Exported authoring values remain literal defaults with the metadata preserved. A new instance created from that exported template still uses localized defaults; restoring a saved instance uses its stored controls.

Units are not a new wire field. Authors explain units in localized labels; numeric min/max/step define graph input bounds. Natural object coordinates and font sizes are logical units; scene handle safety limits are not slider limits. A host reads handle declarations to present direct scene manipulation and bounded numeric entry. Effects may use percentages or other explicitly labelled authoring units. Do not reinterpret those numbers as project coordinates.

## Visual control presets

`controlPresets` and `defaultControlPresetId` are optional together. A document declares 1–64 presets, each with a unique safe `id`, localized `label`, named `theme` and `style` objects (`id`, `label`), and a nonempty `values` map with at most 256 control overrides. The default ID must resolve inside the document. Repeated theme or style identities within a document must have identical labels. Locale maps require English and follow the shared locale contract. The collection uses theme `sniptale-orange`, styles `dark` and `light`, and preset IDs `sniptale-orange-dark` and `sniptale-orange-light`; document IDs identify the effect without style suffixes. Several presets may share a theme/style pair when they represent distinct named settings. The existing `presets` authoring timeline snapshots are a separate concept and do not define these visual variants.

Visual overrides may address only declared non-text controls in the explicit groups `appearance`, `typography`, `processing` or `animation`. Object handle x/y bindings are protected independently of group. Text, geometry, content, unclassified controls and unknown IDs cannot be overwritten. Values follow the existing primitive control contract: finite numbers within min/max and options membership, or color strings. Numeric step remains an editing increment, not a quantization rule. Color syntax is the existing string boundary, not a new CSS parser. Unknown fields, duplicate IDs, unresolved defaults and invalid overrides reject the document. Defaults need not equal a preset after authoring edits.

`validateEffectV1ControlPresetValues(document, values)` checks unknown built-in or persisted user override payloads against a validated document and returns `ok` and diagnostic code/path/message entries. `applyEffectV1ControlPresetValues(document, current, values)` validates and returns a new merged map or throws; `applyEffectV1ControlPreset(document, current, presetId)` resolves a built-in preset and uses the same check. They never initialize missing instance values, mutate inputs, silently skip invalid overrides or reset unspecified controls. Hosts must validate the document before invoking these helpers. Portable parser diagnostics use the same override validation owner.

On creation, initialize all primitive controls, resolving localized text once in the editor locale, then apply the selected visual preset (host preference if valid, otherwise the declared document default). On an existing instance apply the selected preset values over its current controls; preserve text, scene anchors and unrelated user edits. Do not resolve text again. Restore, duplicate and history replay retain the saved controls instead of reapplying the preset. Store preset selection identity separately from actual controls if needed; manual changes may produce a custom visual state. User preset naming, settings, backup and default preferences belong to the host. Imported user override payloads must pass the same SDK validator before use. The SDK authoring viewer exposes the visual selector, records the change in editor history and preserves preset definitions in document export.

## Editing a target effect region

An optional `editorRegion` declares one rectangular editing region inside a `targetEffect` input. It does not move the source clip, change processing scope or create a standalone object. The declaration requires a safe `id`, localized `label`, `kind: "rect"`, `units: "percent"`, `position: "available-space"`, an `inset` fraction in 0–0.25, and four distinct `xControl`, `yControl`, `widthControl`, `heightControl` bindings. Each binding references a bounded number control in the geometry group without enumerated options. Position bounds stay within 0–100. Dimension minimums are positive and maximums cannot exceed `100 - 200 * inset`, ensuring that the rectangle fits even when its axis is the shorter target dimension. The graph must use the same declared coordinate convention; metadata does not alter drawing commands.

For logical target dimensions W and H, padding is `inset * min(W,H)`, region width is `W * widthControl / 100`, height is `H * heightControl / 100`, left is `padding + (W - 2 * padding - regionWidth) * xControl / 100`, and top follows the same rule. Thus 0 and 100 mean the start and end of available travel, not the rectangle center. Values remain resolution-independent, and device pixel ratio never enters this calculation. `resolveEffectV1EditorRegion(document, controls, size)` returns that target-local rectangle or null when absent. `updateEffectV1EditorRegion(document, currentControls, proposedRect, size)` validates finite geometry and returns a four-control patch, clamping movement and size to declared bounds. Zero available travel retains the corresponding current position value. Helpers require a validated document, use defaults for missing controls, reject invalid numeric inputs and do not mutate state or quantize continuous pointer motion to slider step.

The host selects a particular targetEffect instance and displays its region in the scene by applying the target's actual placement, crop, rotation and zoom mapping. Before calling the update helper, invert that mapping into the same logical coordinate space as the effect's source bitmap. The host must not guess bindings from effect or control IDs. Commit all four fields as one undoable interaction; cancel restores the original patch. Numeric inspector changes and canvas gestures share the same instance control state. Saved controls, history, duplication, preview, thumbnails and export must use those values. A track or aggregate effect uses the dimensions of its corresponding input stage. A host without region interaction can still render the document and expose numeric controls, but cannot claim direct region manipulation is implemented. This SDK change supplies the declaration and coordinate helpers; Extension owns the overlay, hit testing, pointer lifecycle and editing commands.

## Source time and interval time

The renderer consumes document-local `time` and normalized `progress`. It does not know the project playhead, trim, source handles or playback rate. For a generated annotation clip, compute `localTime = sourceStart + (projectTime - startTime) * playbackRate`, then `progress = localTime / document.duration`. Render only the active source range. A trim advances sourceStart by the trimmed amount multiplied by playbackRate. A split gives the right instance the left instance's sourceStart plus the split offset multiplied by playbackRate. Neither operation restarts the entrance. The same mapping must be used for live preview, cached frames, thumbnails and export.

An explicitly stretched FX or transition interval of length L maps its full source duration D with `playbackRate = D / L` and initial sourceStart=0. This normalized-interval policy changes speed, not the graph duration or graph implementation. Subsequent trim and split preserve that chosen mapping rather than fitting each remaining fragment to the entire document again. No implicit loop, frozen last frame or hidden restart is defined. The host owns available source handles and clamps editing to them.

A representative thumbnail is a host/catalog recommendation, not a new Effect v1 field: the collection's midpoint `document.duration * 0.5` is nontransparent. Timeline strips sample local source times through the same mapping. A visible thumbnail does not imply that the zero-time frame should be made opaque. Object selection follows [objectLayout](effect-object-layout.md), never animated alpha.

## RGBA and processing order

A targetEffect receives one current RGBA `source` and returns the complete processed RGBA image. Its result replaces that stage's input. Do not draw the old source or a demonstration background behind the returned bitmap. Clip, track and aggregate chains each pass the immediately preceding stage's result to the next effect; target scope does not change graph semantics. Bitmap ownership and disposal remain the host's responsibility.

Transitions receive isolated `from` and `to` RGBA frames, including generated annotations, before lower tracks are added. A weighted crossfade draws from with opacity 1-p onto a cleared surface and to with opacity p using `lighter`. This interpolates premultiplied color and alpha; drawing a fully visible from and merely fading to with source-over does not remove from under transparent to pixels. A wipe uses complementary clips rather than retaining the old frame underneath the revealed region. Compose lower tracks exactly once after obtaining the transition output.

The blend whitelist includes source-over, screen, lighter, source-atop and destination-in. Source-atop applies decoration while preserving destination alpha. Destination-in masks the existing result with the source alpha; it does not paint the source colors. Both work through the existing styled drawing commands and compositePass. Use an isolated renderPass when masking only part of a composition. Unknown blend values are validation errors, not a request to substitute another mode.

The SDK viewer presents graph targetEffect RGBA directly. Its MP4 output explicitly flattens onto black because that output format does not carry canvas alpha; the raw renderFrameBitmapForExport result remains RGBA for host composition. Compare raw frames before this final opaque encoding step. Imported graph failures must surface to the host. Selection of a built-in fallback is host policy and must not conceal a corrupt imported graph.
