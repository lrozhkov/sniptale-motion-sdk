# Sniptale Motion

Локальный комплект для создания и проверки декларативных эффектов Sniptale Effect v1. Промежуточный кандидат поддерживает создание, валидацию и Studio с отдельными ревизиями проекта. Studio безопасно подхватывает внешние изменения файлов. Экспорт создаёт переносимый JSON с ассетами. Browser proof проверяет эффект в обычном viewer и sandbox. Обновление версии пакета и установка skill ещё не готовы. Пакет не опубликован; полный strict и платформенная приёмка ещё не завершены.

Нужны Node.js 22.12 или новее и npm. Установите полученный архив командой `npm install --global /полный/путь/sniptale-motion-0.1.0.tgz`. Репозиторий и инструменты разработки для работы не нужны. Установка не загружает браузер и не запускает lifecycle-скрипты пакета.

Выполните `sniptale-motion --help`, затем `sniptale-motion doctor`. Создайте рабочую папку командой `sniptale-motion init my-motion`, перейдите в неё и выполните `sniptale-motion new my-effect`. Эффект появится в `effects/my-effect/effect.sniptale-effect.json`. Проверьте его командой `sniptale-motion validate effects/my-effect/effect.sniptale-effect.json`.

Для целевого эффекта используйте `new my-effect --kind targetEffect`, для перехода — `--kind transition`. Относительные ассеты разрешаются от папки JSON; другой корень задаётся через `validate <файл> --asset-root <папка>`. Пути за пределами корня ассетов отклоняются. Статическая валидация не подтверждает рендер в браузере.

Команды `init` и `new` не заменяют существующие проекты и эффекты. При отказе записи команда завершается с ошибкой; частичная папка может остаться. Перед повтором проверьте её содержимое и выберите новую папку или идентификатор. Исходники пользователя автоматически не удаляются. Рабочая папка содержит `effects/`, `exports/` и `.tmp/`.

Опция `--json` возвращает один JSON-результат в stdout без прогресса. Коды завершения: 0 — успех, 1 — ошибка операции или невалидный эффект, 2 — неверные аргументы; остановка Studio сигналом возвращает 130 для SIGINT и 143 для SIGTERM. По умолчанию справка на русском; `--locale en` включает английскую справку. `sniptale-motion docs` показывает эту инструкцию; `--version` показывает установленную версию. Команда doctor проверяет запуск установленного Chrome, затем Edge, затем отдельного управляемого Chromium и сообщает выбранный канал и фактическую версию. Для проверки конкретного канала используйте `doctor --browser-channel chrome|msedge|chromium`. Отсутствие браузера не мешает созданию, валидации и экспорту. Для browser proof используйте `sniptale-motion prove effects/my-effect/effect.sniptale-effect.json`; `--asset-root` задаёт корень ассетов, `--browser-channel chrome|msedge|chromium` выбирает один канал без fallback. Команда открывает отдельную headless-сессию, импортирует эффект через обычный UI и проверяет завершённые кадры на границах таймлайна, повторяемость, видимость, изменение controls и runtime binding reads. Для целевого эффекта и перехода проверяются разные временные медиа и отсутствие этих медиа в экспорте. Также проверяются быстрые перемещения времени и восстановление после перезапуска sandbox. Сетевые запросы страницы за пределы двух локальных origins блокируются. Исходник не изменяется; временный проект под `.tmp/` удаляется при завершении.

Из рабочей папки выполните `sniptale-motion studio` или `sniptale-motion studio /путь/к/проекту`. CLI открывает установленный браузер и остаётся запущенным; Ctrl+C закрывает оба локальных сервера. `--no-open` выводит адрес без открытия браузера. `studio --no-open --json` выдаёт один JSON с адресами сессии, после чего ожидает остановки. Каждый запуск выделяет два свободных loopback-порта; адрес сессии действителен до остановки команды. Браузер при установке пакета, диагностике или запуске Studio не скачивается. Драйвер playwright-core включён в npm-архив; дополнительная установка Node-пакетов для него не нужна. Чтобы установить отдельный Chromium, явно выполните `sniptale-motion browser install`. Это сетевая операция, которая использует штатный установщик Playwright и не заменяет системные Chrome/Edge. В Linux системные библиотеки могут потребовать отдельной установки администратором: https://playwright.dev/docs/browsers#install-system-dependencies . Ctrl+C прерывает установку и её дочерние процессы; после отказа команду можно повторить.

Studio читает документы `effects/<id>/effect.sniptale-effect.json` и ассеты внутри соответствующей папки эффекта. Идентификатор документа должен совпадать с именем папки эффекта. Невалидный эффект показывает диагностику и не добавляется в каталог. Доступ к каталогу требует токен из адреса текущей сессии; сервер не раздаёт рабочую папку целиком. Для сохранения правок используйте меню «Сохранить ревизию проекта». Результат создаётся эксклюзивно под `effects/<id>/revisions/<uuid>/`, содержит самодостаточный Effect v1 JSON с ассетами и не заменяет исходник. «Ревизии проекта» позволяет явно принять сохранённую ревизию либо исходный документ для загрузки в редактор; смена выбранной ревизии требует отдельного подтверждения в панели обновления. Выбор записывается в `effects/<id>/current-revision.json`: принятие ревизии сохраняет исходный документ, а выбор «Исходный документ» возвращает его в каталог. При активной ревизии внешняя запись исходника не меняет выбранную ревизию. Незавершённые или повреждённые ревизии не принимаются; после отказа незавершённая папка может остаться для проверки. Если ответ при сохранении потерян, проверьте список ревизий перед повтором. Studio проверяет каталог каждую секунду. Валидное изменение исходника или ассета загружается автоматически, когда редактор свободен и локальных правок нет. Невалидная, частичная или удалённая запись сохраняет последнее рабочее состояние. Новые эффекты добавляются в список без смены текущего эффекта. При локальных правках обновление требует подтверждения: сначала Studio сохраняет их отдельной ревизией, затем загружает новую версию. Изменение выбора исходника или ревизии также требует подтверждения; внешняя запись исходника при активной ревизии не заменяет её. Во время воспроизведения, экспорта или перетаскивания обновление ожидает завершения операции.

Для переносимого экспорта выполните `sniptale-motion export effects/my-effect/effect.sniptale-effect.json --output exports/my-effect.sniptale-effect.json`. Можно указать файл отдельной ревизии вместо исходника. CLI проверяет документ и ассеты, встраивает их в результат и создаёт новый файл; существующее назначение не перезаписывается. Родительская папка назначения должна существовать. При ошибке исходник остаётся неизменным; после прерывания проверьте назначение перед повтором, поскольку готовый файл мог быть опубликован до получения результата команды. В JSON-результате доступны размер и SHA-256. Экспорт не заменяет browser proof: поле runtime остаётся `not-run`. Результат prove содержит фактическую версию и канал браузера, версию toolkit, SHA-256 материализованного входа и отдельные результаты проверок. Неподвижный, невидимый или не реагирующий на controls результат не проходит proof. Если control не имеет допустимого альтернативного значения, результат указывает `NO_ALTERNATE`. Это проверка поведения, а не художественная оценка; воспроизводимость между разными версиями браузера не обещается. Обновление версии установленного пакета пока не реализовано.

For English help, run `sniptale-motion --help --locale en`. Install the supplied archive with `npm install --global /absolute/path/sniptale-motion-0.1.0.tgz`. Run `sniptale-motion init my-motion`, enter that directory, then run `sniptale-motion new my-effect` and `sniptale-motion validate effects/my-effect/effect.sniptale-effect.json`. Existing projects and effects are never replaced. Use `--json` for machine results. This intermediate build provides static validation; Run `sniptale-motion studio` inside the project to open its effects in your installed browser; use `--no-open` to print the session URL and Ctrl+C to stop both servers. Each session uses two separate loopback ports. The project directory is not exposed as a static web root. Use the “Save project revision” menu to persist editable changes under `effects/<id>/revisions/<uuid>/`. “Project revisions” explicitly selects a revision or the original. Loading that selection requires confirmation in the update bar and retains the original file. Incomplete or damaged revisions are not adopted. Studio checks for file changes every second. Valid changes load when the editor is idle and has no local edits. Invalid, partial or deleted files retain the last working state. New effects appear without changing the current selection. If local edits exist, confirming an update first saves them as a separate revision. A change of the selected revision also requires confirmation. Playback, export and drag operations defer updates. Use `sniptale-motion export effects/my-effect/effect.sniptale-effect.json --output exports/my-effect.sniptale-effect.json` to create a portable JSON with embedded assets. A revision document can also be the input. The destination parent must exist; existing destinations and source files are never replaced. After an interrupted operation, check whether the complete destination already exists before retrying. The JSON result includes byte length and SHA-256; runtime proof remains `not-run`. Run `sniptale-motion doctor` to probe installed Chrome, Edge, then managed Chromium. Use `doctor --browser-channel chrome|msedge|chromium` to select one channel. The result records the actual browser version. No browser is downloaded by installation, diagnosis or Studio. The archive bundles playwright-core. To download separate Chromium explicitly, run `sniptale-motion browser install`; this does not replace Chrome or Edge. On Linux, system libraries may require an administrator: https://playwright.dev/docs/browsers#install-system-dependencies . Ctrl+C stops installation and its child processes. Run `sniptale-motion prove effects/my-effect/effect.sniptale-effect.json` for browser proof. Optional `--asset-root` selects the asset root; `--browser-channel chrome|msedge|chromium` selects one channel without fallback. Proof imports through the normal release UI, checks completed timeline frames, repeatability, visibility, controls, runtime binding reads, transient-media isolation and sandbox restart recovery. Page requests outside the two local origins are blocked. It retains the original and removes its temporary project under `.tmp/`. Results record the toolkit version, actual browser version/channel and materialized-input SHA-256. Frozen, invisible or unresponsive results fail; a control without a valid alternate reports `NO_ALTERNATE`. This does not replace artistic review or promise identical output across browser versions. Диагностики CLI содержат код, структурную позицию и подсказку без копирования значений из документа и ассетов. Неизвестные имена полей в позиции заменяются на `<field>`; известные имена берутся из схемы. Это также относится к репозиторным effect:validate и effect:prove, которые вызывают тот же продуктовый CLI.

CLI diagnostics provide a code, structural location and guidance without copying document or asset values. Unknown field names in locations become `<field>`; known names come from the schema. Repository effect:validate and effect:prove use the same product CLI.
